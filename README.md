# STM32 PWM Console with FreeRTOS for RGB LED Control (v2.0.0)

This project provides a **FreeRTOS-based firmware** for the **STMicroelectronics B-U585I-IOT02A Discovery Kit** to control an external RGB LED using PWM signals. The PWM duty cycle for each color channel (Red, Green, Blue) is set dynamically via commands sent over a UART console, with all operations managed by FreeRTOS tasks.

A key feature of this project is its independence from proprietary IDEs like STM32CubeIDE. It uses a modern, script-based build system with a `config.yaml` file, a Python Makefile generator, and standard open-source tools like `make`, `GCC`, `OpenOCD`, and `GDB`.

This `main` branch represents **v2.0.0**, the FreeRTOS-enhanced version of the project.

## Features

### Core Features
- **FreeRTOS Integration**: Full real-time operating system support with preemptive multitasking
- **Dynamic PWM Control**: Controls an RGB LED using three PWM channels generated by TIM2
- **UART Console**: Advanced command-line interface over USART1 with interrupt-driven reception
- **Multi-Task Architecture**: Separate tasks for UART processing, PWM control, and system monitoring
- **Real-Time Performance**: Deterministic timing with FreeRTOS scheduler

### Technical Features
- **IDE-Independent**: Fully configured to be built and managed from the command line
- **Custom Build System**: Uses a `config.yaml` file for all project paths, flags, and settings
- **Script-Generated Makefile**: Python script (`makefile_gen.py`) generates robust Makefiles
- **Open-Source Debugging**: Pre-configured for debugging with `OpenOCD` and `GDB`
- **Modular Code**: Clean separation between application logic, FreeRTOS tasks, and STM32CubeMX drivers
- **Configuration Management**: YAML-based FreeRTOS configuration with automatic header generation

### FreeRTOS Features
- **Preemptive Scheduling**: High-priority tasks can preempt lower-priority ones
- **Task Management**: Three independent tasks with different priorities
- **Memory Management**: Dynamic memory allocation with heap_4
- **Interrupt Handling**: Proper FreeRTOS interrupt integration
- **Error Handling**: Comprehensive error hooks and assertion support

## Architecture Overview

The system is built around FreeRTOS with three main tasks:

1. **HeartbeatTask** (Priority 1): System monitoring and LED heartbeat
2. **UartConsoleTask** (Priority 2): UART command processing
3. **LedPwmTask** (Priority 2): PWM control and effects processing

All tasks communicate through well-defined interfaces and use FreeRTOS primitives for synchronization and timing.

## FreeRTOS Task Structure

### Task Priorities
- **Priority 1**: HeartbeatTask (lowest priority)
- **Priority 2**: UartConsoleTask, LedPwmTask (medium priority)

### Task Descriptions

#### HeartbeatTask
- **Purpose**: System health monitoring and visual feedback
- **Function**: Blinks the green LED every 500ms to indicate system is alive
- **Stack Size**: 128 bytes
- **Period**: 500ms

#### UartConsoleTask
- **Purpose**: Process incoming UART commands
- **Function**: Parses commands like `r=255`, `g=128`, `b=64` and updates PWM values
- **Stack Size**: 256 bytes
- **Period**: 10ms (non-blocking processing)

#### LedPwmTask
- **Purpose**: PWM control and effects processing
- **Function**: Handles PWM updates and can be extended for effects
- **Stack Size**: 128 bytes
- **Period**: 10ms

## Hardware Setup

### 1. RGB LED Wiring

The PWM signals are generated on pins **PA0, PA1, and PA2**, which are available on the **STMod+ (CN3)** connector.

| LED Pin | Resistor | Board Pin | STMod+ Pin |
| :------ | :------- | :-------- | :--------- |
| Red     | 330Ω     | `PA0`     | CN3 Pin 1  |
| Green   | 330Ω     | `PA1`     | CN3 Pin 4  |
| Blue    | 330Ω     | `PA2`     | CN3 Pin 2  |
| Cathode | -        | `GND`     | CN3 Pin 5  |

**Critical Note on Pin Multiplexing**: By default, the STMod+ connector pins are configured for SPI. To use them as GPIO/PWM, pin **PH13** must be driven **HIGH**. This is handled automatically in the `MX_GPIO_Init()` function.

### 2. UART Console Wiring

This board features a built-in ST-LINK V3 which provides a **Virtual COM Port (VCP)** over the same USB cable used for programming and debugging. The VCP is connected to `USART1` of the STM32U5 microcontroller.

- **Connection**: Simply connect your computer to the board using the **USB Type-C ST-LINK connector (CN8)**
- **No external serial adapter is needed**
- Your computer will automatically detect a new serial port (e.g., `/dev/ttyACM0` on Linux, or `COMx` on Windows)

## Build Instructions

1. **Generate the FreeRTOS Configuration**:
    ```sh
    python3 generate_freertos_config.py
    ```

2. **Generate the Makefile**:
    If you ever change `config.yaml` or add new source files, you must regenerate the Makefile.
    ```sh
    python3 makefile_gen.py
    ```

3. **Build the Project**:
    Run `make` to compile the code.
    ```sh
    make
    ```
    The final `.elf`, `.bin`, and `.map` files will be located in the `build/` directory.

4. **Clean the Build**:
    To remove all generated build files, run:
    ```sh
    make clean
    ```

## Flashing the Board

Ensure `STM32_Programmer_CLI` is installed and accessible in your PATH. Connect the board via the ST-LINK USB connector and run:

```sh
make flash
```

This command will build the project if necessary, connect to the board using the SWD interface, write the firmware, and reset the device.

## Debugging

This project supports standard command-line debugging with OpenOCD and GDB.

1. **Start the OpenOCD Server**:
    In your first terminal, start OpenOCD. It will wait for a GDB connection.
    ```sh
    make debug
    ```

2. **Start the GDB Client**:
    In a second terminal, launch GDB. It will automatically connect to the OpenOCD server.
    ```sh
    make debug-gdb
    ```
    You can now use standard GDB commands (`c` to continue, `b` to set a breakpoint, `p` to print variables, etc.).

## Usage

1. Connect the board to your computer
2. Open a serial terminal with the following settings:
    - **Port**: The VCP port (e.g., `/dev/ttyACM0` or `COMx`)
    - **Baud Rate**: 115200
    - **Data Bits**: 8
    - **Parity**: None
    - **Stop Bits**: 1
3. Reset the board. The onboard green LED should start blinking (heartbeat)
4. In the serial terminal, type commands to set the color and press Enter:
    - `r=255`  (Set Red to max brightness)
    - `g=50`   (Set Green to low brightness)
    - `b=0`    (Turn Blue off)
    - `r=128 g=64 b=255` (Set all channels at once)

### Command Format
- **Single Channel**: `channel=value` (e.g., `r=255`)
- **Multiple Channels**: `r=value g=value b=value` (e.g., `r=128 g=64 b=255`)
- **Value Range**: 0-255 (8-bit resolution)

## Troubleshooting

### FreeRTOS Issues
- **Scheduler Won't Start**: Check interrupt priority configuration in `freertos_config.yaml`
- **Tasks Not Running**: Verify task priorities and stack sizes
- **Memory Issues**: Increase heap size in FreeRTOS configuration

### Hardware Issues
- **LEDs Don't Turn On**:
    1. Double-check your wiring, especially the common cathode to GND
    2. Confirm that `PH13` is being set HIGH in the firmware
    3. Make sure you are using a common-cathode LED

### Build Issues
- **Build Fails**:
    1. Ensure the `arm-none-eabi-gcc` toolchain is in your system's PATH
    2. If you added new files, remember to run `python3 makefile_gen.py`
    3. Regenerate FreeRTOS config if you modified `freertos_config.yaml`

### Flashing Issues
- **Flashing Fails**:
    1. Verify that `STM32_Programmer_CLI` is installed and in your PATH
    2. Check that the board is properly connected via the ST-LINK USB port
