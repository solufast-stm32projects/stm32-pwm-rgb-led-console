# STM32 PWM Console for RGB LED Control (v1.0.0)

This project provides a bare-metal firmware for the **STMicroelectronics B-U585I-IOT02A Discovery Kit** to control an external RGB LED using PWM signals. The PWM duty cycle for each color channel (Red, Green, Blue) is set dynamically via commands sent over a UART console.

A key feature of this project is its independence from proprietary IDEs like STM32CubeIDE. It uses a modern, script-based build system with a `config.yaml` file, a Python Makefile generator, and standard open-source tools like `make`, `GCC`, `OpenOCD`, and `GDB`.

This `main` branch represents **v1.0.0**, the foundational version of the project.

## Features

- **Dynamic PWM Control**: Controls an RGB LED using three PWM channels generated by TIM2.
- **UART Console**: A simple command-line interface over USART1 to set color values (e.g., `r=255`, `g=128`, `b=0`).
- **IDE-Independent**: Fully configured to be built and managed from the command line.
- **Custom Build System**: Uses a `config.yaml` file for all project paths, flags, and settings, and a `makefile_gen.py` script to generate a robust Makefile.
- **Open-Source Debugging**: Pre-configured for debugging with `OpenOCD` and `GDB`.
- **Modular Code**: Clean separation between application logic (`src/`), headers (`include/`), and STM32CubeMX-generated drivers (`cube/`).

## Hardware Setup

### 1. RGB LED Wiring

The PWM signals are generated on pins **PA0, PA1, and PA2**, which are available on the **STMod+ (CN3)** connector.

| LED Pin | Resistor | Board Pin | STMod+ Pin |
| :------ | :------- | :-------- | :--------- |
| Red     | 330Ω     | `PA0`     | CN3 Pin 1  |
| Green   | 330Ω     | `PA1`     | CN3 Pin 4  |
| Blue    | 330Ω     | `PA2`     | CN3 Pin 2  |
| Cathode | -        | `GND`     | CN3 Pin 5  |

**Critical Note on Pin Multiplexing**: By default, the STMod+ connector pins are configured for SPI. To use them as GPIO/PWM, pin **PH13** must be driven **HIGH**. This is handled automatically in the `MX_GPIO_Init()` function in this project.

### 2. UART Console Wiring

This board features a built-in ST-LINK V3 which provides a **Virtual COM Port (VCP)** over the same USB cable used for programming and debugging. The VCP is connected to `USART1` of the STM32U5 microcontroller, which is what this firmware uses for the console.

-   **Connection**: Simply connect your computer to the board using the **USB Type-C ST-LINK connector (CN8)**.
-   **No external serial adapter is needed.**
-   Your computer will automatically detect a new serial port (e.g., `/dev/ttyACM0` on Linux, or `COMx` on Windows). This is the port you will use in your serial terminal application.

## Build Instructions

1.  **Generate the Makefile**:
    If you ever change `config.yaml` or add new source files, you must regenerate the Makefile.
    ```sh
    python3 makefile_gen.py
    ```

2.  **Build the Project**:
    Run `make` to compile the code.
    ```sh
    make
    ```
    The final `.elf`, `.bin`, and `.map` files will be located in the `build/` directory.

3.  **Clean the Build**:
    To remove all generated build files, run:
    ```sh
    make clean
    ```

## Flashing the Board

Ensure `STM32_Programmer_CLI` is installed and accessible in your PATH. Connect the board via the ST-LINK USB connector and run:

```sh
make flash
```

This command will build the project if necessary, connect to the board using the SWD interface, write the firmware, and reset the device.

## Debugging

This project supports standard command-line debugging with OpenOCD and GDB.

1.  **Start the OpenOCD Server**:
    In your first terminal, start OpenOCD. It will wait for a GDB connection.
    ```sh
    make debug
    ```

2.  **Start the GDB Client**:
    In a second terminal, launch GDB. It will automatically connect to the OpenOCD server.
    ```sh
    make debug-gdb
    ```
    You can now use standard GDB commands (`c` to continue, `b` to set a breakpoint, `p` to print variables, etc.).

## Usage

1.  Connect the board to your computer.
2.  Connect your USB-to-Serial adapter and open a serial terminal with the following settings:
    - **Port**: The one corresponding to your adapter (e.g., `/dev/ttyUSB0` or `COM3`).
    - **Baud Rate**: 115200
    - **Data Bits**: 8
    - **Parity**: None
    - **Stop Bits**: 1
3.  Reset the board. The onboard green LED should start blinking.
4.  In the serial terminal, type commands to set the color and press Enter. The format is `<channel>=<value>`, where the value is between 0 and 255.
    - `r=255`  (Set Red to max brightness)
    - `g=50`   (Set Green to low brightness)
    - `b=0`    (Turn Blue off)

## Troubleshooting

-   **LEDs Don't Turn On**:
    1.  Double-check your wiring, especially the common cathode to GND.
    2.  Confirm that `PH13` is being set HIGH in the firmware. This was the key fix to enable the STMod+ pins for GPIO.
    3.  Make sure you are using a common-cathode LED. If you have a common-anode LED, you must connect its common pin to `3.3V` instead of `GND`.

-   **Build Fails**:
    1.  Ensure the `arm-none-eabi-gcc` toolchain is in your system's PATH.
    2.  If you added new files, remember to run `python3 makefile_gen.py` to update the `Makefile`.

-   **Flashing Fails**:
    1.  Verify that `STM32_Programmer_CLI` is installed and in your PATH.
    2.  Check that the board is properly connected via the ST-LINK USB port.
